# BPM Agent Studio

Локальный веб-инструмент для построения BPM/BPMN-подобных моделей бизнес-процессов.

## Что умеет

- Собирает BPM-карту из брифа: цель, триггер, результат, роли и конкретные действия.
- Разводит участников по дорожкам, строит последовательность, старт, финиш и связи.
- Позволяет редактировать каждый элемент: название, тип, дорожку, вход, выход, SLA, KPI, результат, риск и onboarding-инструкцию.
- Сохраняет изменения в `localStorage` браузера.
- Экспортирует рабочую модель в JSON, а диаграмму в SVG.
- Экспортирует полную диаграмму в PNG и PDF для просмотра заказчиком.
- Импортирует ранее сохраненный JSON.
- Формирует отдельные представления для аналитики, онбординга и клиентской презентации.
- Поддерживает печать / сохранение в PDF через системный диалог браузера.
- Включает стартовый BPM-шаблон запуска CRM Referral Widget Enterprise MVP по ТЗ.

## Запуск

Приложение работает как статический файл. Можно просто открыть `index.html` в браузере.

Если нужен локальный сервер:

```bash
npm run dev
```

Откройте:

```text
http://127.0.0.1:4173
```

Порт можно переопределить:

```bash
PORT=3000 npm run dev
```

## Формат шагов

В поле "Конкретные действия" удобно писать по одному шагу на строку:

```text
Роль: Действие -> ожидаемый результат [KPI]
```

Пример:

```text
Customer Success: Провести kickoff -> подтверждены цели, роли и критерии успеха [kickoff completion]
```

Агент автоматически определяет дорожку, результат, KPI, риск, onboarding-заметку и тип элемента.

## Стартовая модель по ТЗ

По умолчанию сервис открывает BPM-модель `Запуск CRM Referral Widget Enterprise MVP`.

Она раскладывает ТЗ по:

- проектной команде и дорожкам ответственности;
- roadmap 20-22 недели;
- Sprint 0, архитектуре, CRM spike, dev/staging и CI/CD;
- core modules: SaaS Core, CRM Integration, Partner Registry, Referral Links, Attribution, Commission Rules, Payouts, Analytics, Notifications, Audit Log;
- acceptance criteria, рискам и controlled rollout.

## Проверка

```bash
npm run check
npm run validate
npm run build
```

Ручной smoke-test:

1. Откройте приложение и убедитесь, что стартовая BPM-карта содержит дорожки, действия и связи.
2. Нажмите "Построить BPM" после изменения брифа.
3. Отредактируйте выбранный элемент и проверьте, что статус сохранения меняется на "Автосохранено".
4. Откройте "Клиентская версия" и убедитесь, что презентация строится из той же модели.
5. Экспортируйте JSON и SVG.

## GitHub Pages

Сервис публикуется из отдельной ветки `gh-pages`.

В GitHub откройте `Settings` -> `Pages` и выберите:

```text
Source: Deploy from a branch
Branch: gh-pages
Folder: /root
```

После сохранения GitHub Pages опубликует BPM Agent Studio по адресу:

```text
https://almikhteev-png.github.io/diagramm/
```

В опубликованный артефакт попадают только:

```text
index.html
styles.css
app.js
README.md
.nojekyll
```

Локальные `.env*`, `dist/`, `node_modules/` и старые рабочие папки не публикуются.
